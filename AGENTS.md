# AGENTS.md

VS Code расширение **Custom Explorers for VS Code**

## О проекте
Предоставляет до 10 **контейнеров** `View Container` на `Activity Bar` с динамическими табами. Каждый таб - независимый файловый проводник, где можно выбрать несколько папок для показа под конкретную задачу. Удобно иметь нужные наборы папок, чтоб не заниматься выискиванием нужных файлов в большом проекте.

## Проблемные ограничения VS Code(главная гадость)
- Нельзя создавать контейнер динамически, поэтому резервируем 10 слотов.
- Иконки контейнера обновляются только после перезагрузки всей IDE VS Code.
- Нельзя стандартно сделать удобные классические табы, поэтому рисуем через Webview
- У каждой секции есть минимальная высота и ширина (`min-height` / `min-width`). Если нативный `TreeDataProvider` расположить под Webview - будет большая пустая область, пришлось отказаться от нативного `TreeDataProvider`.

## Стек технологий
- **Core:** TypeScript, VS Code Extension API , Node.js
- **Webview UI:** Vue с **Vapor Mode**. Писать компоненты с учетом Vapor Mode (`features: { vapor: true }`). Пока ещё нет стабильной версии, считаем допустимым.
- **Bundling / Build:** Vite 8, esbuild, TypeScript (`tsc`)
- **Package:** `@vscode/vsce`

## Ключевые команды
- `npm run compile` — сборка Webview (`vite build`) и компиляция расширения (`tsc`).
- `npm run watch` — watch-режим для разработки Webview и Extension.
- `npm run build:prod` — production-сборка (генерация дефолтных иконок, Vite build, esbuild bundle/minify).
- `npm run package` — упаковка в `.vsix` пакет.
- `npm test` — запуск тестов (`test/verify.ts`).

## Структура проекта
- `src/extension.ts` — точка входа и регистрация команд/провайдеров.
- `src/webview/explorerWebviewProvider.ts` — провайдер Webview, координация IPC и работа с файловой системой.
- `src/webview/ui/` — UI на Vue 3.6 Vapor:
   - `src/App.vue` — корневой компонент.
   - `src/components/TabsHeader.vue` — панель вкладок.
   - `src/components/FileTree.vue`, `FileTreeNode.vue` — дерево файлов.
   - `src/components/ContextMenu.vue` — контекстное меню.
   - `src/components/ManagerDashboard.vue` — дашборд управления слотами и диагностика.
- `src/services/storageService.ts` — сохранение конфигурации и кэша в `globalState`.
- `src/services/visibilityService.ts` — управление видимостью слотов в Activity Bar.
- `src/services/iconGenerator.ts`, `src/utils/iconSvg.ts` — генерация SVG-иконок.
- `src/utils/pathUtils.ts` — кроссплатформенная утилита путей.

## Терминология и UI элементы

### 1. Activity Bar (Контейнеры)
- До 10 **Контейнеров** (`View Container`, слоты 1..10).
- Каждый активный контейнер имеет короткое имя (1–3 символа, например `FE`, `API`, `1`), по которому автоматически генерируется векторная SVG-иконка.
- Неактивные слоты скрываются через VS Code context keys.

### 2. Строка состояния (Status Bar)
- `$(layers) Containers (N)` — отображает количество активных контейнеров и открывает Менеджер контейнеров по клику.
- Иконка `$(layers)` (Codicon) выбрана как стандартная визуальная метафора стопки слоёв/контейнеров.

### 3. Контейнер (Container View)
- Единый ультра-легкий Webview (Vue 3 Vapor Mode).
- Состоит из двух зон: сверху панель **Таб**, снизу — **Проводник**.

### 4. Таба (Tab)
- Горизонтальные вкладки в стиле Win32 с компактной высотой (25px).
- В каждой табе настраивается независимый набор подключенных папок (`folders`).
- Источники добавления папок:
  - **Workspace:** выбор каталогов из текущего рабочего пространства (включая multi-root).
  - **С любого диска:** добавление любого каталога или корня диска (`C:\`, `E:\`, `/`) через системный диалог.
- Каждая таба помнит свой независимый список раскрытых узлов (`expandedFolders`).

### 5. Проводник (File Explorer)
Область под табами с деревом файлов и папок активной табы:
- **Пути «As Is»**: пути в конфигурации и `globalState` (`folders`, `expandedFolders`) хранятся в исходном виде (`C:\...`, `/home/...`).
  - Унифицированная кросс-платформенная работа с путями (Windows, Linux, macOS). Преобразования и нормализация выполняются на лету при сравнении и рендере.
  - Корректное отображение корней `getFolderDisplayName` (корень не отображается как пустая строка).
  - Дочерние элементы корней склеиваются безопасно (`joinSubPath`) без дублирования или перемешивания слэшей.
  - Сравнение путей и кэширование регистронезависимы для Windows (`case-insensitive`) и строго сохраняют регистр для Linux и macOS (POSIX).
- **Производительность**: в один момент времени активен максимум один контейнер и строго одна таба в нём (или ни одной). Файловые вотчеры и чтение с диска работают только для папок активной табы. При смене табы кэш `dirCache` сбрасывается.
- **Безопасность ФС**: файловые операции проверяются через `isOperationAllowed`.
- **Гранулярная реактивность:** точечные обновления DOM на основе сигналов Vue Vapor Mode (раскрытие папки или переключение таба обновляет конкретный узел без обхода всего дерева).
- При старте VS Code (`onStartupFinished`) восстанавливается последняя активная таба.
- **Фильтрация скрытых файлов**: см. Tab Exclude Rules.
- **Контекстное меню файлов и папок:**
  - Создание файлов и каталогов (*New File*, *New Folder*).
  - Переименование (*Rename*) и удаление в корзину ОС (*Delete* via OS trash).
  - Копирование пути (*Copy Path*) и открытие в проводнике ОС (*Reveal in File Explorer*).
  - Исключение папки из таба (*Remove from Tab*) без удаления с диска.

### Меню Табы
- Rename Tab...
- Add Folder to Tab... (с иконкой папки)
- Exclude Rules...
- + New Tab...
- Delete Tab (с подтверждением, если таба не пуста)

### Tab Exclude Rules
- `[x] Use VS Code rule (files.exclude)`
- `[x] Use .gitignore from the selected tab's folder or its closest parent`
- Additional Exclude Rules (textarea с glob-паттернами)

**Пересчет Exclude Rules:** выполняется при старте, создании/смене/удалении табы, изменении Workspace, сохранении настроек контейнеров в Менеджере.

### Менеджер контейнеров (Containers Manager)
- Открывается по команде `Manage Containers` (`customExplorer.manage`), клику на Status Bar или кнопке в заголовке панели.
- `[x] Filter containers by current workspace`:
  - Показывает контейнер, если хотя бы одна из его папок находится **внутри** открытого Workspace (проверка `isFolderInWorkspace`, корень диска не считается вхождением).
  - Пустые контейнеры (без папок) всегда видны для первичной настройки.
- **Пересчет видимости контейнеров:** выполняется при старте, изменении Workspace (`onDidChangeWorkspaceFolders`) и сохранении в Менеджере. Не запускается при обычном редактировании таб/папок во избежание внезапного исчезновения активного слота.
- **Таблица 10 слотов:**
  - Номер слота (#1 .. #10)
  - Имя (1–3 символа)
  - SVG-превью сгенерированной иконки
  - Количество таб (`# tabs`)
  - Статус (Active / Inactive)
- **Блок диагностики:** отображает точный объём данных в `globalStorage` (~3.5 КБ), замеряет скорость чтения с диска и задержку IPC, выявляет битые/устаревшие пути и очищает мусор в один клик (`Clean Trash`).
