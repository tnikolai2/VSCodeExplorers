# AGENTS.md

VS Code расширение **Custom Explorers for VS Code**

## О проекте
Предоставляет до 10 **контейнеров** `View Container` на `Activity Bar` с динамическими табами. Каждый таб - независимый файловый проводник, где можно выбрать несколько папок для показа под конкретную задачу. Удобно иметь нужные наборы папок, чтоб не заниматься выискиванием нужных файлов в большом проекте.

## Проблемные ограничения VS Code(главная гадость)
- Нельзя создавать контейнер динамически, поэтому резервируем 10 слотов.
- Иконки контейнера обновляются только после перезагрузки всей IDE VS Code.
- Нельзя стандартно сделать удобные классические табы, поэтому рисуем через Webview
- У каждой секции есть минимальная высота и ширина (`min-height` / `min-width`). Если нативный `TreeDataProvider` расположить под Webview - будет большая пустая область, пришлось отказаться от нативного `TreeDataProvider`.

## Стек технологий
- **Core:** TypeScript, VS Code Extension API , Node.js
- **Webview UI:** Vue с **Vapor Mode**. Писать компоненты с учетом Vapor Mode (`features: { vapor: true }`). Пока ещё нет стабильной версии, считаем допустимым.
- **Bundling / Build:** Vite 8, esbuild, TypeScript (`tsc`)
- **Package:** `@vscode/vsce`

## Ключевые команды
- `npm run compile` — сборка Webview (`vite build`) и компиляция расширения (`tsc`).
- `npm run watch` — watch-режим для разработки Webview и Extension.
- `npm run build:prod` — production-сборка (генерация дефолтных иконок, Vite build, esbuild bundle/minify).
- `npm run package` — упаковка в `.vsix` пакет.
- `npm test` — запуск тестов (`test/verify.ts`).

- `src/webview/explorerWebviewProvider.ts` — провайдер Webview, координация IPC и работа с файловой системой.
- `src/webview/ui/` — UI на Vue 3.6 Vapor:
   - `src/App.vue` — корневой компонент.

### Проводник
- **Пути «As Is»**: пути  в конфигурации и `globalState` (`folders`, `expandedFolders`) храним в исходном виде (`C:\...`, `/home/...`). 
   - Унифицированная кросс-платформенная работа с путями (Windows, Linux, macOS). Преобразования и нормализация выполняются исключительно на лету при отображении и сравнении. 
   - Правильное отображение корней `getFolderDisplayName` (корень чтоб не показывался как песто). 
   - Дочерние элементы корней дисков склеиваются безопасно (`joinSubPath`) без дублирования или перемешивания слэшей (`\` и `/`).
   - Сравнение путей и кэширование регистронезависимы для Windows (`case-insensitive`) и строго сохраняют исходный регистр символов для Linux и macOS (POSIX).
- **Производительность** Может быть активен только максимум 1 контейнер и максимум одна таба в нём, либо ни однй активной табы. Поэтому файловые вотчеры и чтение с диска активны строго для активного таба. При потере активности табы, её кэш памяти `dirCache` сбрасывается.
- **Безопасность ФС**: файловые операции валидируются через проверку допустимости корней (`isOperationAllowed`).
- **Гранулярная реактивность:** Точечные обновления DOM на основе сигналов реактивности (раскрытие папки или переключение таба обновляет конкретный узел без обхода всего дерева).
- Каждая таба хранит свой собственный независимый набор папок и список раскрытых узлов (`expandedFolders`).
- При старте IDE `onStartupFinished` делаем активной последнюю активную табу.
- **Фильтрация скрытых файлов** see Tab Exclude Rules.
- **Контекстное меню файлов и папок:**
  - Создание файлов и каталогов (*New File*, *New Folder*).
  - Переименование (*Rename*) и удаление с отправкой в корзину ОС (*Delete* via OS trash).
  - Копирование пути (*Copy Path*) и открытие в проводнике ОС (*Reveal in File Explorer*).
  - Исключение папки из таба (*Remove from Tab*) без удаления с диска.
